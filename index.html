AI Data Analysis Platform

Enterprise AI 3 Iterations NL2SQL
Business Problem

业务数据海量但分析靠人工，每季度一次，大量业务机会被错过。

Why It Was Hard
  • 大模型上下文窗口限制，原始数据直接灌入导致幻觉
  • NL2SQL 方案遭遇上下文爆炸，查询结果过大时输出质量骤降
Product Thinking
大模型擅长结构化推理，不擅长处理海量原始数据。用特征工程替代原始数据灌入。

1
Phase 1 · 验证可行性
文件上传 + 上下文注入
将 CSV 数据作为上下文直接输入大模型。初步验证可行，但数据量稍大即出现幻觉。
受限于上下文窗口大小，无法满足实际业务数据规模。
2
Phase 2 · 架构转折
NL2SQL + 数据库直连
自然语言转 SQL 查询数据库，绕开上下文限制。但查询结果包含数千条数据时，大模型仍无法有效处理。
SQL 结果过大时，上下文爆炸问题再次出现。
直接把海量原始数据丢给大模型，这条路走不通。必须重新审视大模型的能力边界。
3
Phase 3 · 终局方案
特征提取 + AI 分析
先通过 SQL 提取核心统计特征（总量、均值、标准差等），再将浓缩特征输入大模型分析。
用"特征工程"替代"原始数据灌入"，彻底解决上下文爆炸。
Result
满足80%基础分析需求，分析频率从季度提升至日常。
